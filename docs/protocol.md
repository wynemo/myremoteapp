# 控制通道 v4

本文描述当前实现。JPEG 预览、SOCKS5 TCP 和鼠标控制已实现；H.264、键盘及 WebRTC 尚未实现。

## 连接与认证

- TCP 外层地址由用户指定；连接建立后开启 TCP_NODELAY。
- 仅使用 TLS 1.3，双方都必须出示证书。
- Mac 首次 `serve` 自动生成并持久保存两端身份，导出 `connect.json`。客户端导入该文件后使用其中的客户端身份认证，同时只信任文件指定的 Mac 证书，不加载公共 CA。使用者无需手工操作证书。
- `connect.json` 包含可重复使用的客户端私钥，是访问凭据；Mac 主机私钥只存在 `identity.json` 中。`serve --reset-pairing` 更换身份并撤销旧连接文件。
- TLS 服务名固定为 `remoteapp.local`，ALPN 必须为 `myremoteapp-control/1`。
- 客户端 DNS/TCP/TLS 整体连接超时为 10 秒；服务端 TLS 握手超时为 10 秒。
- TLS 成功之后才能进入应用层协议。当前通过连接文件授权，尚未实现短码在线配对或逐设备授权。
- 可通过 SOCKS5 CONNECT 建立 TCP 通道，支持无认证及用户名/密码认证；目标域名交给代理解析，失败不回退直连。总连接期限覆盖代理协商与 TLS 握手。当前无 WebRTC、UDP 或传输降级逻辑。

## 消息格式

```text
[4 字节无符号大端长度 N][N 字节 UTF-8 JSON]
```

长度只计算 JSON，不包括头部。有效范围为 1～65536 字节；读到超限长度立即拒绝，不按攻击者提供的长度分配内存。单条消息的完整读取与写入各有 10 秒期限，不能靠不断发送少量字节无限延长读取。

消息使用 `type` 字段区分，拒绝未知消息类型、未知字段、截断数据和非法 JSON。

| 方向 | 消息 | 说明 |
| --- | --- | --- |
| 客户端 → 服务端 | `{"type":"hello","version":4}` | 第一条应用消息 |
| 服务端 → 客户端 | `{"type":"welcome","version":4}` | 版本协商成功 |
| 客户端 → 服务端 | `{"type":"ping","sequence":1}` | 往返探测 |
| 服务端 → 客户端 | `{"type":"pong","sequence":1}` | 原样返回序号 |
| 客户端 → 服务端 | `{"type":"goodbye"}` | 结束诊断 |
| 服务端 → 客户端 | `{"type":"error","code":"unsupported_version"}` | 版本不支持，随后结束会话 |
| 服务端 → 客户端 | `{"type":"error","code":"unexpected_message"}` | 状态与消息不匹配，随后结束会话 |

畸形帧、超时和认证失败直接终止，不保证返回应用错误。当前 CLI 不发送周期心跳；空闲 10 秒会结束会话，后续长会话需要另行实现心跳。

## 服务端边界

当前诊断服务最多处理 8 条并发 TCP/TLS 会话，超出的连接立即关闭。这只是资源限制，不表示已经支持多个远程控制者；尚未实现窗口控制权仲裁。

## 后续视频通道要求

以下是设计约束，尚未实现：

- 视频使用独立连接，必须绑定已认证控制会话，不能只凭来源 IP 接入。
- 传输 H.264 编码数据，携带帧序号、采集时间戳、画面尺寸及几何版本。
- 明确定义 Annex B 或 AVCC，协商 profile/level，处理 SPS/PPS 和分辨率切换。
- 发送队列有界；积压时不能随意丢参考帧后继续发送依赖帧，应降低码率/帧率，必要时清空待发送队列并请求新 IDR。
- 坐标只接受画面实际显示区域内的事件，并校验几何版本；断线释放所有输入状态。
- 传输切换需要暂停旧通道、更新代次、请求 IDR 并重置接收缓冲；旧代次数据不再使用。

## JPEG 窗口预览（已实现）

当前 Hello/Welcome 版本为 3，两端需要同时更新。ping/pong/Goodbye 格式不变。客户端完成握手后发送 `{"type":"start_preview"}`，服务端返回 `preview_started` 消息，携带 `window`（id、app、title、width、height）。服务未选择窗口时返回 `no_window_selected` 错误并结束会话。旧服务不支持新消息，客户端会提示更新 Mac 端。

`preview_started` 之后，这条连接只传预览记录，不再交织 JSON 控制消息：

```text
[u32 JPEG 字节数][u32 width][u32 height][u64 sequence][JPEG bytes]
```

整数均为大端。长度 0 表示采集结束，此时不包含后续字段。每帧上限 8 MiB，宽高各为 1～2560，总像素数不超过 2560×1440，客户端在解码前校验 JPEG 内部尺寸与记录头一致，并限制解码内存。当前按 Retina 像素采集，长边最大 2560、短边最大 1440，10 FPS、JPEG 质量 95、4:4:4 色度。两端均需更新以支持更大的画面尺寸。

发送端和接收端均只保留最新帧，静止窗口每秒重发最后一帧以保活；每次读写有 10 秒期限。没有首帧、Mac 锁屏或窗口关闭、持续采集失败及断线时结束预览，不自动改为采集其他目标。Windows SYSTEM 锁屏模式下，桌面切换的短暂采集失败可暂停最多 5 秒；内部清除旧帧并等待新桌面，不发送结束标记，原预览会话恢复后继续使用递增帧序号。超出恢复期限仍结束预览，协议版本及帧格式不变。当前帧通道复用已认证的 TLS/SOCKS5 TCP 连接；后续独立视频通道和 H.264 约束不属于已实现能力。


## 独立鼠标控制连接（已实现）

控制连接独立于 JPEG 视频连接，复用相同 TLS 双向设备认证、目标地址及 SOCKS5 路由。客户端先完成 Hello/Welcome v4，再发送 `start_control`（window_id 必须匹配当前共享窗口）。服务端返回 `control_ready`；仅观看服务返回 `control_unavailable`，已有控制者返回 `control_busy`。

后续使用有界 JSON 控制消息：

- `mouse`：event 包含 frame_sequence（显示帧序号）、x/y（0～65535 的归一化画面坐标）以及 kind；kind.action 为 move、button（button=left/right/middle，down=bool）或 scroll（dx/dy 为有符号整数）。
- `release_input`：释放所有已按下的鼠标按钮，不要求帧序号有效。
- `input_error`：服务端拒绝某次输入并释放按钮，携带 message；窗口可继续显示，客户端把原因展示到终端和窗口标题。
- `ping` / `pong`：每 2 秒心跳，服务端读超时 10 秒。
- `goodbye`：结束控制连接，释放控制权和按钮。

视频帧序号在当前 capture stream 内唯一。Mac 保存最近 128 帧的坐标信息，校验当前窗口尺寸后映射；过期序号、已关闭窗口、锁屏或权限撤销均不继续注入。按钮松开/全部释放不受过期帧限制。控制会话通过 RAII 在 EOF、错误、超时和任务取消时释放按钮及独占控制权。


## 手动密码解锁（v4）

`get_status` 返回 `status`，含 locked 与 unlock_available。客户端结束状态查询会话后再从本地终端隐藏输入密码，避免用户输入期间持有会超时的网络会话。已解锁时不提示密码。

解锁使用一条新的双向 TLS 会话：Hello/Welcome v4 → `unlock` → `[u32 大端长度][UTF-8 密码字节]` → `unlock_result`。密码记录上限 4096 字节，拒绝空值、NUL 和非法 UTF-8，不得序列化进 JSON/Debug 消息。临时密码缓冲区释放时清理。读取期限为 10 秒，客户端等待解锁响应上限 25 秒。

outcome 为 unlocked、rejected、unavailable、busy 或 window_unavailable。每次请求只执行一次系统提交，错误响应不包含密码或底层系统错误详情。主机已解锁但窗口无法恢复时返回 window_unavailable。客户端不自动重试密码。客户端断开、结束或取消请求时，主机设置取消标志，原生代码在写入密码和提交前重新检查。

服务端 unlock 后端仍受当前设备认证、控制台用户、系统签名和辅助功能权限约束；普通只观看/诊断服务不接受解锁。没有密码持久化、钥匙串或“记住密码”协议。
